# Headless execution and resource budgets

Use `blender -b --python-exit-code 1 --python task.py -- ...`. Verify the installed version before relying on API properties. Save the native candidate before previews so a render failure cannot erase the modeling result. Preview from a separate fresh process; never save its temporary material, visibility or camera overrides into the delivery model.

Resolve executable, script, scene, report and render-output paths to absolute paths in the calling process. Loading a BLEND can change relative-path interpretation; do not assume a shell-relative render path stays under the workspace. Blender processes CLI arguments in order: load the scene before setting render output/options, and put the render action last. Check the path reported by the renderer against the intended destination.

On Windows, read [Windows setup](windows-setup.md) for discovery, authorized installation and a 30-second factory-startup probe. `subprocess.run(..., timeout=...)` kills and waits for its direct child on timeout; this is sufficient for the minimal probe, which starts no child programs. It is not a process-tree or RSS guard. Windows modeling defaults to direct Blender CLI with the resource guard disabled. Only if the user explicitly enables resource protection, use a Windows Job Object or another compatible supervisor with process-tree cleanup. Otherwise report that process-tree cleanup and RSS protection are not active; their absence does not block ordinary modeling. Do not run the POSIX guard or Linux example runner as though they supported Windows.

On Windows, do not query system memory during ordinary setup or modeling. Only gather those metrics when the user requests resource diagnostics/protection or a concrete resource failure needs diagnosis. If a query is denied or unavailable, record the metric as unavailable and continue without trying alternate commands, UI tools or permission escalation solely to obtain it. In particular, do not cycle through `Get-CimInstance`, `systeminfo` and other probes. Missing memory telemetry is not a Blender connectivity or modeling failure.

For resource planning on other platforms, use readily available memory information (for example Linux `/proc/meminfo`). One Blender process is the starting point, not a universal concurrency limit. Before choosing parallel execution, assess headroom using a representative job and available evidence; if headroom is unknown, remain sequential instead of blocking the task on telemetry. Serialize costly rendering if budget is tight. Prefer Workbench/solid white output; white materials alone do not make a high-sample path-traced render cheap.

`guarded_run.py` requires Python 3 and POSIX. Timeout handling uses POSIX process groups (Linux tested; macOS untested). Limits must be finite and positive. Optional live RSS limiting is **Linux-only**, includes the process group, and is a sampled guard rather than a hard memory sandbox. Linux `VmRSS`/`MemAvailable` are KiB; the helper converts them to bytes. On unsupported platforms requesting RSS limits fails clearly rather than silently ignoring the limit. On timeout or RSS breach it sends process-group TERM, waits bounded grace, sends KILL if necessary, and reaps its direct child. Terminated orphan descendants can remain zombies until the operating system reaps them; the regression checks they are no longer running. Exit codes: child status normally; 124 timeout; 125 RSS limit. Its JSON records sampled peak RSS, not an exact kernel peak.

Example for a chosen machine budget (not a recommended universal value):
`python3 scripts/guarded_run.py --timeout 120 --max-rss-mib 2048 --report run-01.json -- blender -b --python-exit-code 1 --python build.py`

A tool failure is not evidence the model failed visually. Preserve the log, isolate the error and retry only the affected step. Never report measured resource values from an old run as current.

Generated white previews remove PNG text, EXIF and time chunks without re-encoding image data. This does not remove visible scene information, anonymize BLEND files or sanitize arbitrary external images. The minimal example applies the same cleanup to all three previews.
