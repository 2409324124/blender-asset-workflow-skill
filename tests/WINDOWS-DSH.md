# Windows DSH compatibility observations — 2026-11-01

This is a dated local test report, not hosted CI or a guarantee for every DSH/Blender release. It records an actual DSH-generated asset and independent review; credentials and raw session logs are not included in this repository.

## Environment and isolation

| Item | Observed value |
|---|---|
| OS | Native Windows x64 |
| Node / npm | 24.14.0 / 11.9.0 |
| DSH | `@deepseek-ai/dsh@0.2.1-rc.5` |
| Blender | 5.2.3 LTS, per-user installation |
| Skill source | PR #1 candidate commit `8a3ceba6b60854931caca4136412506ea6e44797` |
| Host mode | CLI `--profile headless --patch <test-overlay> --json` |
| Authentication | Existing saved API key via the official credential service; only `credentials` restored |
| State | Unique workspace, separate `DSH_HOME`, new sessions; discovery restricted to a copied skill |
| Deadline | 120 seconds for the tool probe; 900 seconds for the modeling run |

The credential overlay referenced the original DSH store. No key value was copied into the test workspace or prompt, and the user's main profile was not edited. This was application-state isolation under the same Windows account, not a VM, security sandbox, or independent credential store. Fourteen copied skill source files remained unchanged, excluding generated bytecode.

## Results

- Initial stock-headless attempt after Web key setup failed with `MISSING_CREDENTIAL`.
- The corrected API-key overlay enabled a successful actual model/file-tool probe with a random local marker; exit 0.
- DSH loaded the skill through its skill tool and generated the lamp builder, preview and validation scripts. No old asset or builder was supplied.
- Modeling completed in 622.3 seconds with exit 0, without timeout: 19 meshes, 4,608 triangles and height 0.44744486 m.
- Two repair passes addressed a hidden bulb and 20 degenerate faces in `ShadeNeck`. An incorrect base-footprint assertion was corrected to inspect `BasePlate` rather than whole-model bounds. Failed reports were retained.
- Builder reported 107/107 checks passing after repairs. This count is task-specific evidence, not a universal quality certificate.
- A separate reviewer inspected the actual images, reopened the saved BLEND in a fresh process (1.39 seconds, exit 0), and generated an opening-facing detail preview (3.90 seconds, exit 0). Candidate hash remained unchanged.
- Delivered BLEND SHA-256: `e325eba78129a769abd555b78fa64ea7d9f2dbf7e1bc1efa73faa32cd5194c3b`.

## Not established by this run

- Web-based modeling end to end, despite separate Web startup/model-list checks.
- DSH account sign-in, OAuth/device-login flows, account recovery, or cross-machine credential reuse.
- GLB export, animation, target-engine compatibility, exact collision or exhaustive manifold certification.
- Photorealistic lighting: delivered previews used Workbench material colors. The overall view was a low three-quarter orthographic view, not a strict mathematical isometric view.
- Compatibility of future package releases, every proxy configuration, or an OS-level sandbox.

The later documentation update uses upstream's complete three-entry authentication restore example; this historical modeling run used the narrower API-key entry. Reproduction and acceptance steps are in the [Windows DSH guide](../skills/blender-asset-workflow/references/windows-dsh.md).

## Web workflow findings — 2026-11-01

These observations come from tool-call/result records, visible responses and output files in a separate Web session using the older user-installed skill. They describe snapshots of that run, not an evaluation of the revised instructions. Raw sessions, credentials and private machine paths are omitted.

| Observed problem and evidence | Documentation change |
|---|---|
| The installed skill still required memory discovery. `Get-CimInstance` failed, followed by a second failed attempt with `systeminfo` | Skip ordinary Windows memory discovery; an unavailable metric does not trigger alternate commands or elevation |
| After finding Blender, the agent ran additional engine/device, noise and material-interface probes. One probe accessed nonexistent `CyclesRenderSettings` and failed | Reuse successful execution evidence or run one minimal `bpy` probe, then start the builder; diagnose concrete failures instead of inventorying capabilities |
| The initial segment lasted about 153 seconds and made 17 tool calls. After a progress question, the visible response promised continuation but the turn ended; at that snapshot only `DESIGN.md` existed | A progress question is not cancellation: give a brief status and continue authorized work. Do not imply a finished turn is still executing in the background |
| Later snapshots did contain a saved BLEND, white previews and beauty renders. A snapshot counted 48 edit calls, 20 image reads and a fifth hero image, with changes to pores, roughness, exposure and lighting; no independent reviewer invocation appeared in the inspected calls | Distinguish builder self-refinement from independent QA. Simple requests do not authorize open-ended aesthetic refinement; judge required defects separately from optional preferences |
| Recent color-test renders took roughly 3–6 seconds each, despite the prolonged end-to-end workflow | Do not attribute all delay to Blender rendering. Bound iterative refinement and deliver the requested usable result |
| An earlier saved-file inspection predated subsequent candidate revisions | Recheck the final delivered bytes; older reports cannot certify a revised candidate |
| The Web session loaded the old installed skill, while fixes existed only on the PR branch | Verify the actually loaded path/content before attributing behavior to a revised skill; publishing a PR does not update an existing local installation or loaded conversation |

These observations concern builder self-refinement, not demonstrated exhaustion of independent QA repair capacity. They do not justify changing the existing QA budget. This PR retains the existing default of at most two QA repair passes and its user-defined override. The corrective guidance instead keeps simple modeling proportionate, distinguishes required defects from optional polish, and stops editing once the requested result passes.

These observations establish that this Web session could run Blender, save a candidate and render/read images. They do not establish final export/reimport, independent QA, final delivery, or improved behavior under the revised policy. The policy changes have document/consistency validation only; no new end-to-end modeling run is claimed.
